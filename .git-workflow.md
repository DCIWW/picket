# Git Workflow for Picket Development

## Branch Strategy

The `preview` branch tracks the **latest stable release from upstream** with your OIDC changes on top.

### Current Setup
- **Upstream**: `makeplane/plane` (https://github.com/makeplane/plane)
- **Origin**: `DCWobs/picket` (your fork)
- **Base**: Latest upstream release tag (currently `v1.2.1`)
- **Branch**: `preview` with OIDC authentication + Picket branding

## Updating to New Upstream Releases

When a new upstream release is published (e.g., `v1.2.2`, `v1.3.0`), follow these steps:

### 1. Fetch Latest Upstream
```bash
git fetch upstream
git fetch upstream --tags
```

### 2. Find Latest Release Tag
```bash
git tag -l --sort=-version:refname | head -10
```

### 3. Create New Branch Based on Release
```bash
# Example for v1.3.0
git checkout -b oidc-v1.3.0 v1.3.0
```

### 4. Cherry-pick Your OIDC Changes
```bash
# Get the commit hash of your OIDC merge commit
git log preview --oneline -1

# Cherry-pick it (or use the hash from above)
git cherry-pick dcda3ba677
```

If there are conflicts:
- Resolve them carefully, keeping both upstream changes and your OIDC additions
- For OAuth providers: Keep both Gitea (upstream) and OIDC (yours)
- For error codes: Use next available numbers for OIDC errors
- For branding: Keep "Picket" references

### 5. Update Preview Branch
```bash
git branch -D preview
git checkout -b preview
```

### 6. Push to Origin (when repository is ready)
```bash
git push -f origin preview
```

## Important Notes

1. **Always base on release tags**, not development branches
2. **Test thoroughly** after rebasing to new versions
3. **Keep OIDC config separate** from upstream OAuth providers
4. **Document any new conflicts** for future reference
5. **Version numbers** should track upstream (e.g., 1.2.1) not restart at 1.0.0

## Stash Reference

Your OIDC changes are also saved in git stash:
```bash
git stash list
# stash@{0}: On preview: Stashing OIDC changes before syncing with upstream
```

To view stashed changes:
```bash
git stash show -p stash@{0}
```

## Checking What Changed Upstream

Before updating to a new release:
```bash
# Compare current base to new release
git log --oneline v1.2.1..v1.3.0

# Check specific files that you've modified
git diff v1.2.1..v1.3.0 -- apps/api/plane/authentication/
```

This helps you anticipate potential conflicts.
